# AWS 클라우드 전환 마이그레이션 계획서

> **문서 목표**: GCP vCPU 리소스 부족 문제를 해결하고, 인프라 확장성과 안정성을 확보하기 위해 AWS로 점진적으로 전환하는 전체 과정을 명확하게 정의합니다.

## 1. 최종 목표 (End-Goal)

- **인프라 전환**: 모든 애플리케이션(BE, FE, AI) 및 공유 서비스(Jenkins, DB 등)를 GCP에서 AWS로 이전합니다.
- **CI/CD 고도화**: AWS에 새로 구축한 Jenkins를 기반으로 `dev` 환경은 CD(지속적 배포), `prod` 환경은 CI(지속적 통합)가 적용된 파이프라인을 구축합니다.
- **비용 최적화**: 마이그레이션 완료 후, 더 이상 사용하지 않는 GCP 리소스를 모두 제거하여 비용을 절감합니다.
- **다운타임 최소화**: 프로덕션 환경 이전 시, 계획된 최소한의 시간 내에 작업을 완료하여 서비스 중단을 최소화합니다.

## 2. 마이그레이션 단계별 로드맵

### Phase 1: CI/CD 기반 구축 (현재 진행 중)

- **목표**: AWS 환경에 Jenkins를 구축하고, 자동화된 배포 파이프라인의 토대를 마련합니다.
- **완료된 작업**:
    - [x] Terraform을 사용한 AWS 공유 VPC 및 Jenkins EC2 인프라 프로비저닝
    - [x] Ansible을 사용한 Jenkins 서버 초기 설치 및 설정
    - [x] Jenkins Credential 등록 (GitHub PAT, Docker Hub)
    - [x] `deployment-guide.md`에 Jenkins 설정 내용 문서화
- **남은 작업**:
    - [ ] 각 서비스(BE, FE, AI)별 `Jenkinsfile` 작성하여 파이프라인 코드화
    - [ ] `dev` 환경(develop 브랜치): Build → Test → Push → Deploy 자동화
    - [ ] `prod` 환경(main 브랜치): Build → Test 까지만 자동화 (배포는 수동 승인)

### Phase 2: 개발(`dev`) 환경 인프라 이전

- **목표**: `dev` 환경의 모든 애플리케이션 서버를 AWS에 구축합니다.
- **주요 작업**:
    - [ ] **Terraform**: `dev` 환경용 EC2 인스턴스, 보안 그룹, 네트워크 설정 등 AWS 리소스 정의
    - [ ] **Ansible**: `dev.ini` 인벤토리 파일에 새로 생성된 AWS 서버 정보 업데이트
    - [ ] **WireGuard**: 신규 AWS `dev` 서버와 기존 인프라 간의 VPN 터널링 설정 및 연결 확인

### Phase 3: 개발(`dev`) 환경 배포 및 검증

- **목표**: Phase 1에서 구축한 Jenkins 파이프라인을 통해 `dev` 애플리케이션을 AWS에 배포하고 안정성을 검증합니다.
- **주요 작업**:
    - [ ] Jenkins 파이프라인을 실행하여 `dev` 서버(BE, FE, AI)에 애플리케이션 배포
    - [ ] 배포된 `dev` 환경의 기능 및 성능 통합 테스트 수행
    - [ ] 내부 DNS 또는 서비스 디스커버리 설정 변경 (필요시)

### Phase 4: 프로덕션(`prod`) 환경 이전 및 트래픽 전환

- **목표**: Phase 2, 3의 성공 경험을 바탕으로 `prod` 환경을 AWS로 이전하고, 실제 사용자 트래픽을 전환합니다.
- **주요 작업**:
    - [ ] **인프라 이전**: Phase 2의 작업을 `prod` 환경에 동일하게 반복 적용
    - [ ] **배포 및 검증**: Phase 3의 작업을 `prod` 환경에 동일하게 반복 적용
    - [ ] **트래픽 전환**:
        - 사전 공지를 통해 점검 시간 확보
        - DNS 레코드(Load Balancer 주소 등)를 신규 AWS `prod` 환경으로 변경
        - 전환 후 즉시 모니터링을 통해 서비스 안정성 집중 확인

### Phase 5: GCP 리소스 정리 (Decommissioning)

- **목표**: AWS 환경이 완전히 안정화된 것을 확인한 후, 불필요한 GCP 리소스를 제거하여 비용을 최적화합니다.
- **주요 작업**:
    - [ ] 최소 1-2주간 AWS 환경 모니터링 후 롤백 계획이 불필요하다고 판단
    - [ ] Terraform `destroy` 명령을 사용하여 `dev`, `prod` 환경의 GCP 리소스 제거
    - [ ] 마지막으로 Terraform Backend용 GCS 버킷 등 Bootstrap 리소스 제거
