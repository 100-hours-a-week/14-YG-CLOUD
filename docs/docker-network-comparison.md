# 3-Tier Docker 네트워크 적용 방안 비교

## Option 2: 완전 Docker 네트워크 (모든 서버에 Docker)

### 구조
```
┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐
│  Database Tier  │  │  Backend Tier   │  │    AI Tier      │
│  (Docker)       │  │  (Docker)       │  │  (Docker)       │
├─────────────────┤  ├─────────────────┤  ├─────────────────┤
│ moongsan-net    │  │ moongsan-net    │  │ moongsan-net    │
│                 │◄─┤                 │  │                 │
│ MySQL:3306      │  │ Redis:6379      │  │ FastAPI:8100    │
│ (Container)     │  │ Spring:8080     │  │ (Container)     │
│                 │  │ (Containers)    │  │                 │
└─────────────────┘  └─────────────────┘  └─────────────────┘
    Docker Net          Docker Net          Docker Net
```

### 장점
1. **일관된 네트워크 모델**: 모든 서비스가 동일한 방식
2. **서비스 디스커버리**: 컨테이너 이름으로 통신 가능
3. **격리성**: 각 서비스 완전 격리
4. **이식성**: 환경 간 쉬운 이동

### 단점
1. **Database 성능**: 컨테이너 오버헤드
2. **복잡성**: 볼륨 마운트, 백업 복잡
3. **학습 곡선**: 팀의 Docker 숙련도 필요

## Option 3: 완전 호스트 네트워크 (Docker 미사용)

### 구조
```
┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐
│  Database Tier  │  │  Backend Tier   │  │    AI Tier      │
│  (Host)         │  │  (Host)         │  │  (Host)         │
├─────────────────┤  ├─────────────────┤  ├─────────────────┤
│                 │  │                 │  │                 │
│ MySQL:3306      │◄─┤ Redis:6379      │  │ FastAPI:8100    │
│ (Native)        │  │ Spring:8080     │  │ (Native)        │
│                 │  │ (Native)        │  │                 │
└─────────────────┘  └─────────────────┘  └─────────────────┘
    Host Network        Host Network        Host Network
```

### 장점
1. **최고 성능**: 네트워크 오버헤드 없음
2. **단순성**: 전통적인 배포 방식
3. **디버깅 용이**: 직접적인 프로세스 관리

### 단점
1. **환경 의존성**: OS/패키지 버전 충돌
2. **격리 부족**: 서비스 간 영향
3. **배포 복잡성**: 환경별 설정 차이
