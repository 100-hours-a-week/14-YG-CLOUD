# 📝 문서 유지보수 가이드

> **5개 고정 문서 구조**를 유지하면서 변경사항을 체계적으로 문서화하는 방법

## 🎯 핵심 원칙

### ✅ **5개 문서 고정 구조 유지**
- 새로운 문서 생성 금지 
- 모든 변경사항은 기존 5개 문서 내에서 업데이트
- 상세 분석이 필요한 경우만 `archive/` 에 임시 저장 후 통합

### ✅ **변경사항 추적 프로세스**
1. **변경 발생** → 2. **영향 분석** → 3. **문서 업데이트** → 4. **검증**

## 🔄 변경사항별 상세 업데이트 가이드

### 1. 🏗️ **인프라 변경시**

#### **대상**: `infrastructure-complete-guide.md`

```bash
# 변경 사항 예시
- 새로운 GCP 리소스 추가
- 네트워크 구성 변경  
- 인스턴스 타입 변경
- 비용 최적화 적용
```

**업데이트 위치**:
- **Part 4: 현재 아키텍처 상태** → 실제 구성 반영
- **Part 3: 최종 결과** → 비용 변경시 업데이트
- **Part 2: 최적화 여정** → 새로운 최적화 추가시

### 2. 🔧 **배포 프로세스 변경시**

#### **대상**: `deployment-guide.md`

```bash
# 변경 사항 예시
- Terraform 모듈 변경
- Ansible 플레이북 변경
- 배포 순서 변경
- 새로운 환경 추가
```

**업데이트 위치**:
- 해당 단계의 명령어 및 설명 업데이트
- 새로운 전제조건이 있다면 추가
- 변경된 출력 결과 반영

### 3. 🔐 **보안 설정 변경시**

#### **대상**: `security-guide.md`

```bash
# 변경 사항 예시
- 새로운 암호화 키 추가
- VPN 설정 변경
- 접근 권한 변경
- 새로운 보안 정책 적용
```

**업데이트 위치**:
- 해당 Part의 설정 단계 업데이트
- **Part 4: 종합 보안 체크리스트** 업데이트

### 4. 🔧 **문제해결 방법 추가시**

#### **대상**: `troubleshooting-guide.md`

```bash
# 변경 사항 예시
- 새로운 오류 패턴 발견
- 해결 방법 개선
- 새로운 컴포넌트 문제
- 긴급 대응 절차 변경
```

**업데이트 위치**:
- 해당 컴포넌트 섹션에 새로운 문제 추가
- 기존 해결방법 개선
- **긴급 상황 대응** 절차 업데이트

```bash
git diff HEAD~1 HEAD
```

```bash

# 3. security-guide.md
# 4. troubleshooting-guide.md
```

## ⚠️ 주의사항

### **❌ 하지 말아야 할 것**
- 새로운 `.md` 파일 생성
- 중복 내용을 다른 문서에 복사
- 임시로 만든 분석 문서를 그대로 방치
- 변경사항을 문서화하지 않고 넘어가기

### **✅ 해야 할 것**
- 모든 변경사항을 즉시 해당 문서에 반영
- 상세 분석이 필요하면 `archive/` 에 임시 저장 후 통합
- 문서 간 일관성 유지
- 정기적으로 문서 정확성 검증
